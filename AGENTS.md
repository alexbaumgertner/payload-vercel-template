# AGENTS.md

Indie SaaS starter: landing page + waitlist + changelog, with Payload CMS admin at `/admin`.
Solo-founder project — optimize for shipping small, correct, reversible changes.

## Stack (pinned — do not upgrade or add libraries without being asked)

Next.js 16 (App Router, Turbopack) · Payload 3 · PostgreSQL (Neon in prod) via `@payloadcms/db-postgres` ·
React 19 · TypeScript 6 strict · CSS Modules · Zod 4 · Vitest 5 · Playwright · Vercel (+ Vercel Blob for media).

## Commands

- `pnpm dev` — http://localhost:43127 (admin: `/admin`)
- `pnpm check` — typecheck + lint + unit tests. **Run before saying a task is done.**
- `pnpm test:int` — Vitest against real Postgres (`app_test` DB, never the dev DB)
- `pnpm test:e2e` — Playwright (desktop + mobile), reuses a running dev server
- `pnpm generate:types` — after ANY collection/field change; commit `src/payload-types.ts`
- `pnpm generate:importmap` — after adding custom admin components
- `pnpm migrate:create <name>` — before merging schema changes (see "Database")
- `pnpm seed` — idempotent demo data + admin user

## Layout

```
src/app/(frontend)/   public site — Server Components by default
src/app/(payload)/    Payload admin + API — generated, do not edit
src/collections/      Payload collections (schema + access + hooks)
src/access/           reusable access functions
src/features/<name>/  schema.ts (Zod, shared client/server) · service.ts (server-only, takes `payload`) · actions.ts ('use server') · queries.ts (server-only reads)
src/components/<Name>/<Name>.tsx + <Name>.module.css
src/lib/              env (Zod-validated), payload client, formatting
src/migrations/       generated by Payload — never hand-edit applied migrations
tests/unit|int|e2e/   *.unit.spec.ts · *.int.spec.ts · *.e2e.spec.ts
docs/decisions.md     why things are the way they are — read before re-architecting
```

## Rules

- Data access goes through the Payload Local API in `service.ts` / `queries.ts`. No raw SQL, no Drizzle calls.
- Public reads use `overrideAccess: false`. Anything the Local API writes on behalf of a visitor must be validated with Zod first.
- Mutations from the UI are Server Actions returning a typed state object — not route handlers.
- Every new env var: add to `src/lib/env.ts` schema AND `.env.example`.
- Styling: CSS Modules + tokens from `globals.css`. No Tailwind, no CSS-in-JS, no inline styles except dynamic values.
- UI must handle empty, loading and error states and work at 360px width.
- No `any`, no `@ts-ignore`. Prefer `satisfies` and inferred Zod types.
- Hooks that call `revalidatePath` must respect `req.context.disableRevalidate`.

## Database

- Local dev uses Payload **push** mode (schema syncs automatically). Never run `pnpm migrate` against the dev DB.
- Production only changes via migrations: after changing collections run `pnpm migrate:create <name>` and commit the files.
  Vercel runs `pnpm build:vercel` → `payload migrate` → `next build`.
- Never connect to the production (Neon) database from the agent.

## Workflow

1. Tasks touching >3 files or the data model: plan first, wait for approval.
2. Implement in small steps; write/extend tests next to the change.
3. Verify: `pnpm check`, `pnpm test:int` for services/collections, `pnpm test:e2e` or browser check for UI.
4. Conventional commits (`feat:`, `fix:`, `chore:` …), one logical change per commit.
